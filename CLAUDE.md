# CLAUDE.md

cda-discorl: DiscoRL's learning mechanisms (and the frozen Disco103 rule) for gym-CDA's PPO
Learner, as a gym-CDA training extension named `discorl`. Start at `docs/README.md`;
`docs/architecture.md` is how it plugs in, `docs/development.md` how to test and release it.

## Rules

1. **`third_party/disco_rl` is never edited.** It is DeepMind's code (the ChuaCheowHuan/disco_rl
   fork) as a pinned submodule, installed unchanged; `test_packaging.py` checks it. Import what
   `disco_rl` provides through `cda_discorl/upstream.py` or `disco103/bridge.py`; write locally
   only what must be torch or is specific to gym-CDA. Moving the pin: skill `discorl-bump-disco-rl`.
2. **Settings live in `cda_discorl/config.py`.** A new key goes in `DEFAULTS` with its rule in
   `validate`; a default that `disco_rl` defines is read from it, not restated.
3. **Run the suite with pytest:** `OMP_NUM_THREADS=1 python -m pytest -q` (about 120 tests,
   under two minutes on a CPU). A test that needs a real `Algorithm` subclasses `RealRun` in
   `tests/conftest.py`; add checks to an existing run before adding a new one, because each run
   costs seconds. Before committing: `ruff format .` and `pyflakes cda_discorl tests`.
4. **A fix lands with a test that fails without it.** Show it failing on the old source first.
5. **Reviews file, they do not fix.** Verify each claim first (skill `discorl-verify-finding`),
   then file it as a GitHub issue with a severity (`S1-blocking` to `S4-minor`), a kind (`bug`,
   `enhancement`, `documentation`, `test-gap`, `refactor`), `agent` or `human` (who can resolve
   it), and an issue type (Bug, Task or Feature). An issue that needs both gets sub-issues, one
   label each.
6. **Docs move with the code.** A change to a component, a setting, a metric or a test file updates
   `docs/components.md`, `docs/configuration.md`, the test table in `docs/development.md` §2 and
   the changelog, as `docs/development.md` §5 lists. `docs/findings.md` records measured runs:
   add new results, do not rewrite old ones.

## Facts worth not re-deriving

- Five components, each off by default and applied to `modules` only: `target_policy`, `adv_ema`,
  `value_norm`, `policy_prediction` (experimental), `disco103` (experimental). `disco103`
  excludes `target_policy`, `policy_prediction` and `value_norm`.
- Every loss change goes through gym-CDA's `_policy_value_loss` seam, so MoE and JEPA terms stay.
- gym-CDA pin: `>=2.1,<3` (lazy extension import, `extra_trunk_heads`).
- Issue footer: `_Generated by [Claude Code](https://claude.ai/code)_`. Link to files, not
  `#fragment` anchors, in issue text.
